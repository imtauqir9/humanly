Inside Humanly

Everything that happens between typing a topic into a form and having an audited, publishable article on disk — the screens, the ten pipeline stages, the argument three models have about the draft, and the files that fall out the other end.

The shape of a run

One topic in, an argued-over article out

The web form and the CLI are the same program. POST /api/start spawns seo_writer.py as a subprocess with the flags the form set, and streams its stdout back to the browser line by line. Nothing about the pipeline changes because a browser started it.

Flow one — write a new article

Six moments, start to finish

This is what a person actually sees. Roughly eight to twelve minutes wall-clock for a default-length article, most of it spent in stages 5 and 6.5.

MOMENT 1
GET /login

The door

Starting a run spends real money — about seventeen model calls across three vendors — so every route sits behind a password, JSON APIs included. Eight bad attempts from one IP buys a five-minute lockout. HTTP basic auth is accepted too, so curl -u works against the same endpoints.

GET /healthz → {"ok": true, "protected": true} the one open route, so a health check needs no credential
MOMENT 2
GET /

Write new, or evaluate a draft

Two tabs over one log. Write new takes a topic and, more usefully, an intent — a sentence about who it is for and what they should leave with. The agent reads the intent and extracts the 2–4 word search query itself, so you never have to guess at keywords. Length moves every structural number together, not just the word target.

Article Topic Semantic caching for LLMs Intent convince platform engineers this is worth the infra cost Keywords (optional — left blank, the agent derives them) Edition 31 Length Default — 2,500–3,500 words ▾ ☑ Also write a LinkedIn post ☑ Also write a 2–3 minute video script ☐ Also design a LinkedIn share card
MOMENT 3
POST /api/start

Hand off to the pipeline

The form validates, then returns a job id immediately. The browser opens an EventSource on the stream; the server has already spawned the CLI in a thread and is pushing its stdout into a queue. Closing the tab does not kill the run — the job is only forgotten once it actually ends, so a reconnect finds it still there.

POST /api/start → { "job_id": "8f3c…" } python seo_writer.py "Semantic caching for LLMs" \ --intent "…" --words default --edition 31 --linkedin --video
MOMENT 4
GET /api/stream/<job_id>

Watching it work

The live log is the CLI's own output, unmodified. Every stage announces itself, and a keepalive comment goes out between stages so a proxy does not cut the connection during a long call. A pipeline that goes quiet for too long reports that it stopped responding; a browser that merely loses its connection does not — those arrive as two different events, deliberately.

[INTENT] Extracting search keywords from intent... [STEP 1] SERP Research for: semantic caching llm [STEP 4] Generating article outline - Default (2,500–3,500 words) [STEP 5] Writing article content, target 3000 words [STEP 6] Humanizing content (pass 3 - targeted repair) [STEP 6.5] Agents writer claude-sonnet-5 anthropic auditor gpt-5.5 openai judge gemini-2.5-pro gemini [STEP 6.5] Writer responding to 4 finding(s)
MOMENT 5
GET /api/articles

The card appears

On the done event the grid refreshes and the new article slides in at the top, with only the buttons its run actually produced. A run without --video has no Visual track button, because there is no visual track.

Semantic Caching for LLMs: Cut Latency Without Cutting Corners Sep 08, 2026 · 3,140 words · 7 images [ HTML ] [ DOCX ] [ Markdown ] [ LinkedIn ] [ Video script ] [ Visual track ] [ Review ]
MOMENT 6
/review · /deck · /usage

Read what happened

The article is the obvious output; the audit trail is the interesting one. Review shows every finding with all three voices attached and whether it was applied. Visual track presents the video script as timed slides with the on-screen note per beat. Usage says what the run cost.

Flow two — the pipeline itself

Ten stages, plus three you can switch on

Each stage consumes the previous stage's output rather than the raw topic, which is why the outline can enforce structure the writer then has to fill, and why the auditor has something concrete to compare the draft against.

STEP 1Research

SERP research

Pulls the live top results for the derived keyword through SerpAPI and reads what is already ranking — the angles taken, and the gap none of them fill. Without a SerpAPI key the stage still runs, on the model's own knowledge, and says so.

outranking titles, snippets, the gap to aim at
STEP 2Angle

Title refinement

Picks the angle and the target keyword the article will actually be built around, informed by what stage 1 found rather than by the topic you typed.

outworking title, target keyword
STEP 3Coverage

Key takeaways

Names what the article must cover to beat the pages already ranking. These become the coverage checklist the auditor scores against later — a promise made now that has to be kept in stage 6.5.

outthe must-cover list
STEP 4Structure

Outline

Fixes the skeleton before a word is written: H2 count, H3s per section, image slots, a comparison table where the topic genuinely has something to compare, and FAQ questions written as H3s ending in a question mark — the shape the FAQ schema is later built from.

outsection tree, image slots, FAQ questions
set bythe length you picked
STEP 5Draft

Write

The full draft in one pass, grounded in the research and in whatever sits in sample-articles/. Those samples are the reason the output reads like a particular person rather than like a language model with a house style.

out2,500–3,500 words
readssample-articles/
STEP 6Voice

Humanize — and then measure it

Pass one rewrites against a 24-item checklist of AI tells. Pass two makes the model audit its own rewrite. Pass three is the one that matters: a scanner counts what survived — banned vocabulary, title-cased headings, inline-header bullets, em dashes, uniformly-lengthed sentences — and hands the model that exact phrase list to repair, nothing else.

If the count goes up, pass 2 is kept. A repair pass that makes things worse is thrown away rather than shipped, which is the difference between a humanizer and a vibe.

outthe draft, in your voice
calls3
STEP 6.4GEO

The answer block

Forty to sixty words placed directly under the H1, written to still make sense when an answer engine quotes it with no surrounding page. It is generated before verification on purpose, so the auditor fact-checks it like any other passage instead of it slipping through as metadata.

outone extractable paragraph
STEP 6.5Verification

The argument

A second model audits the draft against the brief from stages 3 and 4, the writer answers back, a third model settles what is still contested, and only what survives gets applied. Then it re-audits. The whole of the next section is this stage.

outrevised article
out_review.md, _review.json
callsup to 8
STEP 7Metadata

SEO meta

Title, meta description and slug, written against the finished article rather than the topic. These land in the HTML head, in Open Graph and Twitter tags, and in the Article JSON-LD — not in a sidecar file no crawler will read.

outtitle, description, slug
STEP 8Media

Images

Real photographs resolved through Google Images or Unsplash for each image slot the outline reserved, downloaded and embedded into the DOCX rather than hot-linked. No placeholders.

out6–8 images, embedded
STEP 9–11Optional

LinkedIn post, video script, share card

All three read the finished, verified article. The post is written to what actually works on the platform: 150–220 words, the first two lines carrying it because that is all LinkedIn shows before “see more”, no engagement bait, at most three hashtags. The script is six timed beats, each with the visual that carries it — and the prompt explicitly rejects “stock footage of a developer typing”, because it illustrates nothing. Runtime is measured from the narration alone.

out_linkedin.md
out_video.md
out_thumbnail.html

Step 6.5 in full

The draft has to survive an argument

One model checking its own work agrees with itself. So the audit is pushed onto a different vendor, the writer is allowed to push back, and a third model rules on what is still contested. Every default in this loop is chosen so that a stage whose job is to check the article can never be the thing that destroys it.

Which model plays which role

Roles are pushed onto the most distinct vendors your keys allow, and the auditor moves off the writer's vendor first — a blind spot shared by writer and auditor means the finding is never raised at all. The writer stays on Anthropic in every configuration, because the style prompts were tuned against it; swapping the writer changes the product rather than checking it.

Keys presentWriterAuditorJudge

Auditor

Writer

Disputed. The source is cited two paragraphs down.

Judge

Uphold. The citation two paragraphs down covers a different claim.

Flow three — evaluate a draft

Point the same three agents at writing they didn't do

The auditor works by comparing an article against the brief it was written to — and a file you hand it has no brief. So one call reconstructs the brief the document appears to have been written to, from its own heading structure and the promises it makes the reader. From there it is the identical loop.

# the same thing from a terminal python seo_writer.py "Semantic caching for LLMs" \ --audit ./drafts/my-post.md \ --intent "convince platform engineers this is worth the infra cost" \ --apply

What the HTML carries that a plain export doesn't

A real head

title · description · canonical · og · twitter

The canonical is written only when SITE_URL is set. A wrong canonical is worse than none, so a blank value omits it rather than guessing.

Article schema

JSON-LD · Article · Person

Publication date, word count, author and publisher, the article's images, and every source as a named citation.

FAQ schema

JSON-LD · FAQPage

Built from the article's own FAQ — which is why the outline insists those headings are H3s ending in a question mark. Anything that isn't a real question is skipped rather than shipped malformed.

Named citations

IDC — https://idc.com (accessed …)

A publisher name and an access date, not a bare URL. Attributable citations carry weight; naked links don't.

The quotable paragraph

40–60 words, under the H1

Written to survive being lifted out of the page entirely, and fact-checked in 6.5 like every other passage.

A comparison table

where the topic has something to compare

Required by the outline when it makes sense. Tables are the passage assistants most often quote whole.

The surfaces

Six routes worth opening

/

Library

The form, the live log, and every article generated so far with only the buttons its run earned.

/review/<slug>

Verification review

The roster that argued, per-round scores, and every finding with the auditor, writer and judge on it — and whether it was applied.

/deck/<slug>

Visual track

The video script as fixed 1920×1080 slides, one per beat: the beat name, the line, the on-screen visual, then the narration.

/usage

Token usage

Totals, cost per article, a per-model breakdown with bars, and a per-day history.

/output/<file>

The files

Served straight from disk. DOCX downloads; HTML and Markdown open in a tab.

/healthz

Health

The only unauthenticated route, and it reports whether the deployment is actually locked — so you can check from outside.

What it costs

Counted, never estimated

Token counts come from what each API reports — usage.input_tokens on Anthropic, prompt_tokens on OpenAI, usage_metadata on Gemini. Cost is the softer layer: a model with no price on file still has its tokens counted and simply reports no dollar figure rather than a wrong one, and the dashboard treats that run's total as a floor.

When it goes wrong

Every failure has a decided answer

A pipeline that spends a dozen model calls before it can fail needs a rule for each way it can fail. None of these are exception handlers written after the fact; each one is a decision about what the user should be left holding.

What breaksWhat happensWhy
The auditor's call failsVerification ends, the article stands as written, and the run says it was not checkedThe stage that checks the article must not be the thing that destroys it
The audit comes back truncatedThe round is discarded, the article survivesA half-parsed audit shouldn't cost you the whole run
The writer never answers a findingIt is appliedSilence is acceptance, not a veto
The judge returns no rulingThe writer's text standsAn unruled dispute isn't a loss
A vendor is down mid-runThat role falls back to Claude and says so in the transcriptAn outage shouldn't cost an article a dozen calls deep
The browser loses its connectionNothing — the job keeps running and the stream reconnectsA dropped socket is not a pipeline failure, and is reported as a separate event
The pipeline goes silentReported as stopped responding, with the minutes namedAn indefinite spinner tells you less than a timeout does
The pipeline crashesThe last forty lines are echoed to the server logOtherwise the output only ever existed in a tab that has since closed
